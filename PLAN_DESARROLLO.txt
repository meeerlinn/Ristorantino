FASE 1 — COMPLETAR EL FLUJO DE CAJA (PRIORITARIO)
================================================================================

  OBJETIVO: Que el cajero pueda abrir la caja, cobrar mesas,
            emitir facturas y cerrar la caja.

  ─────────────────────────────────────────────────────────────────────────────
  [ ] 1.1 — Pantalla: Gestión de Caja
  ─────────────────────────────────────────────────────────────────────────────
      URL: /caja/
      Vista: gestion_caja(request)

      FUNCIONALIDADES:
        - Muestra el arqueo activo del usuario (si existe)
        - Si no hay arqueo activo: formulario para abrir uno (monto_apertura)
        - Botón "Abrir Caja" → POST /caja/abrir/ → crea Arqueo(estado='Abierto')
        - Botón "Cerrar Caja" → POST /caja/cerrar/<arqueo_id>/
            → pide monto_cierre_real
            → calcula diferencia_arqueo
            → cierra el arqueo (estado='Cerrado', fecha_cierre=now())

      DATOS EN PANTALLA (tiempo real del turno activo):
        - Total vendido (suma DocumentoTributario del arqueo)
        - Cantidad de facturas emitidas
        - Monto esperado en caja vs. monto real ingresado
        - Diferencia (sobrante/faltante)

  ─────────────────────────────────────────────────────────────────────────────
  [ ] 1.2 — Pantalla: Cobro de Mesa y Facturación
  ─────────────────────────────────────────────────────────────────────────────
      URL: /pedido/<id>/cobrar/
      Vista: cobrar_pedido(request, pedido_id)
      Permiso: Solo rol 'Cajero'

      FLUJO:
        1. Muestra resumen del pedido (items, subtotal, descuento, total)
        2. Permite buscar/seleccionar cliente (por RUC/CI via AJAX)
           o usar cliente genérico (RUC=0)
        3. Selecciona método de pago (Efectivo / Tarjeta / QR / Mixto)
        4. Al confirmar:
             → Crea DocumentoTributario (calcula IVA 10% alimentos)
             → Crea PedidoDocumento (vincula pedido ↔ documento)
             → Actualiza Arqueo.monto_cierre_sistema += total
             → Actualiza Pedido.estado_pago = 'Pagado'
             → Actualiza Pedido.fecha_cierre = now()
             → Cambia Mesa.estado = 'Sucia'
        5. Redirige al salón con mensaje de confirmación

  ─────────────────────────────────────────────────────────────────────────────
  [ ] 1.3 — Completar estado "Entregado" en cocina
  ─────────────────────────────────────────────────────────────────────────────
      PROBLEMA: La cadena Pendiente → Cocina → Listo existe pero "Entregado"
                no se marca en ningún lugar.

      CAMBIOS:
        - En comanda.html: mostrar items con estado 'Listo' con badge verde
        - Agregar botón "Entregar" por item → POST cambiar_estado 'Entregado'
        - El mozo confirma la entrega al cliente desde su pantalla
        - Esto completa el ciclo cocina → mesa → cliente

FASE 2 — DASHBOARD DE KPIs
================================================================================

  OBJETIVO: Panel analítico para administrador con métricas clave del negocio.

  URL: /kpis/
  Vista: dashboard_kpis(request)
  Permiso: Solo roles 'Cajero' / Administrador

  FILTRO TEMPORAL:
    - Botones rápidos: Hoy / Esta semana / Este mes
    - Selector de rango personalizado (fecha desde / fecha hasta)
    - Endpoint AJAX: GET /kpis/datos/?desde=X&hasta=Y  → JSON con todos los datos
    - Los gráficos se actualizan sin reload de página

  ─────────────────────────────────────────────────────────────────────────────
  WIDGETS DE RESUMEN (tarjetas superiores)
  ─────────────────────────────────────────────────────────────────────────────

    [ ] Total de ventas del período
          → suma de DocumentoTributario.monto_total (estado='Vigente')

    [ ] Cantidad de pedidos cerrados
          → Pedido.filter(estado_pago='Pagado', fecha en rango)

    [ ] Ticket promedio
          → total_ventas / cantidad_pedidos

    [ ] Margen bruto estimado
          → suma de PedidoDetalle.cantidad * (precio_historico - producto.costo_insumo)

  ─────────────────────────────────────────────────────────────────────────────
  GRÁFICOS (usar Chart.js — sin dependencias extra)
  ─────────────────────────────────────────────────────────────────────────────

    [ ] Gráfico 1: Ventas por día
          → Tipo: línea o barras
          → Datos: Pedido agrupado por fecha (TruncDay)

    [ ] Gráfico 2: Métodos de pago
          → Tipo: torta / doughnut
          → Datos: agrupado por metodo_pago

    [ ] Gráfico 3: Top 10 productos más vendidos
          → Tipo: barras horizontales
          → Datos: suma PedidoDetalle.cantidad por producto

    [ ] Gráfico 4: Top 10 productos por margen
          → Tipo: barras
          → Datos: (precio_historico - costo_insumo) * cantidad por producto

  ─────────────────────────────────────────────────────────────────────────────
  TABLAS Y WIDGETS ADICIONALES
  ─────────────────────────────────────────────────────────────────────────────

    [ ] Rendimiento por mozo
          → Pedidos cerrados, total vendido, ticket promedio
          → Agrupado por Pedido.mozo

    [ ] Rotación de mesas
          → Tiempo promedio de ocupación (fecha_cierre - fecha_apertura)
          → Por mesa y por sector

    [ ] Performance de cocina
          → Tiempo promedio desde 'Pendiente' hasta 'Listo' en FlujoEstado
          → Detecta productos que tardan más
